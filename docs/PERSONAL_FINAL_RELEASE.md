# 个人网易云音乐 beta.27：功能边界与维护

## 收藏专辑页

`app/.../feature/albumlibrary/` 集中保存分页、页面偏好、展示、队列准备和 ViewModel。只通过原 `LibraryApi` 读取收藏、原 `PlaylistRepository` 读取曲目、原 `PlaybackController` 播放；不修改这三份公共契约。卡片直接调用 `LibraryGridItem`，图片、标题、歌手与原音乐库同步。

顶部顺序播放与随机播放均以当前搜索结果及页面排序为准。随机只重排专辑，专辑内保持服务端原曲序；同一首曲目出现在不同专辑中时保留各自位置。准备并发限制为三张专辑，全部读取成功后才替换旧队列；失败、取消、换号和较新的播放请求都不能提交旧准备结果。准备期间显示可取消的临时进度，不保留底部“选择一种播放方式”栏目。

收藏列表按 200 张分页，只发布完整结果；检测服务端重复页，缓存按 UID 隔离。默认三列，设置支持 1–5 列、按歌手分组及最近收藏/名称排序。多人合辑不按歌曲的实际表演者拆开。布局单独保存在 `collected_albums_layout`，不触及曲库/关联。主页面只有一个有界 `LazyVerticalGrid`，没有弹层或可滚动父容器及随测量变化的高度反馈。

旧底栏 `music` 项原位置和显隐映射为 `albums`；旧导航序列化名及快照键仍可读取，避免升级丢失其他页面栈。显示名称与代码域改为专辑，旧独立 MusicScreen 已删除，主页 MusicContent/MusicSections 恢复基线原组件。

## 歌单倒序记忆

`app/.../feature/playlist/ui/PlaylistTrackSortRepository.kt` 与 `PlaylistTrackSortViewModel.kt` 负责独立持久化，原 `PlaylistScreen` 仅接入加载状态和排序回调。按真实账号/访客、歌单/专辑类型和 ID 保存排序维度及倒序方向；不同资源之间互不影响。

偏好恢复完成前不构建歌曲列表，避免默认顺序闪烁及提前触发错误分页。新增曲目使用最新完整列表按规则排序；正在播放的队列保持原样，下次点击播放使用最新排序。快速选择合并并串行写入，未知存储格式不会被默认值覆盖；显式重置仅清理当前资源。无需写云端歌单曲序。

## 歌手专辑筛选

继续复用原资料库匹配及 `artist_album_corrections` 人工纠正存储。页面只保留紧凑匹配计数。资料库设置、手动修正、恢复全部移到歌手更多菜单。恢复全部只关闭当前歌手筛选，不删除绑定与手动记录。

最少曲数的设置、保存 API、过滤及发行版择优规则已全部移除。旧偏好键可留在文件中，代码不再读取；不能为清理冗余开关而清空整个设置文件。资料库识别和手动添加仍可保留短专辑，现场版/歧义版本不会因为曲数少而被提升为录音室专辑。

## 设置归属

| 一级分组 | 入口和职责 |
| --- | --- |
| 音乐库与页面 | 页面与布局（底部入口、个人音乐库、收藏专辑、播放页模式、缩放）；本地音乐与匹配（优先策略、歌曲/专辑关联、备份、扫描）；歌手专辑筛选（资料库默认值） |
| 播放与音源 | 播放与下载（衔接、预缓冲、下载缓存）；音质；音源（严格模式、社区源、UNM）；歌词 |
| 系统与应用 | 设备集成、网络、隐私、储存、关于与诊断 |

各二级入口使用原偏好所有者，不复制扫描器或匹配 ViewModel；设置内返回先回父分类。底部独立页面仍可以排序和隐藏。

## 其他修复与已有数据

导入内容更新时取消并等待旧目标歌单请求，防止旧预览/旧帐号回填到新会话。原样移植官方 `20b94c02` 插件代理 GET/POST 的 4 MiB 响应上限，含无长度与解压响应；不改变其他调用的默认行为。

原有本地优先、双向歌曲/专辑匹配、批量核验、歌曲关联备份、WAV 标签及复合专辑归组、严格换源、文本歌单导入、封面打开歌词、完整时长和两种衔接保留。原弹层的 ExpandedSheetScrollBoundary 继续处理向上触底余量；新增专辑主页面单独作连续上滑和静止采样回归。

## 兼容性与验证边界

共同基线和当日官方更新审查见 `PERSONAL_FINAL_AUDIT.md`。静态自动合并、隔离集成编译和当前个人包的实测是不同证据，最终结果以随 APK 验证清单为准。未来官方修改公共播放/媒体会话/导航或本地扫描接口时仍需适配和回归，不能保证永远自动兼容。

Fork 的 Release 不会自动跟随官方。后续应读取官方更新、在独立集成分支合并或变基、解决差异、执行关键回归和 Release/R8 构建，再以同一包名和签名提供新的个人 APK。本轮不自动推送或发布 GitHub Release。
